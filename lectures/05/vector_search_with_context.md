# ベクトル検索の動作比較：search_materials() と search_materials_with_context()

## 比較対象

| | 実験１ | 実験２ |
|---|---|---|
| ログ | `benchmark_logs/20261122-004433` | `benchmark_logs/20261122-032337` |
| 検索ツール | `search_materials()` のみ | `search_materials()` ＋ `search_materials_with_context()` |
| 取得範囲 | ヒットしたページのみ | ヒットしたページ ＋ 前後 1 ページ |
| 指示文 | — | `search_materials_with_context()` を既定で使い、簡単な用語質問のときだけ `search_materials()` を使う |

比較したのは「ベクトル検索」方式（`app.agent --trace`）だけです。全文投入・Tree・Graph は実験間でコードが変わっていません。質問は同じ 3 問です。

- Q1: 第２回の説明では、LoRAは何を固定し何を学ぶか？QLoRA は何を加えるか。
- Q2: 第３回の説明では、コンパクションとセッションをまたぐメモリの違いは？日々のメモは全部長期メモリになる？
- Q3: 今回作ったRAGの実測平均応答時間と正答率は？

## 1. ツール呼び出しの違い（traces.md）

| 質問 | 実験１ | 実験２ |
|---|---|---|
| Q1 | `search_glossary(LoRA)` → `search_glossary(QLoRA)` → `search_materials(LoRA QLoRA 固定)`（3 回） | `search_glossary(LoRA)` → `search_materials_with_context(LoRA QLoRA 固定)`（2 回） |
| Q2 | `search_materials(コンパクション セッション メモリ 長期メモリ 日々のメモ)`（1 回） | `search_materials_with_context(コンパクション セッションをまたぐメモリ 日々のメモ 長期メモリ)`（1 回） |
| Q3 | `search_materials(実測平均応答時間 正答率 RAG)`（1 回） | `search_materials_with_context(RAG 実測 平均応答時間 正答率)`（1 回） |

- 実験２では 3 問とも `search_materials_with_context()` が使われ、`search_materials()` は一度も呼ばれませんでした。
- 質問が用語質問の Q1 でも `search_materials_with_context()` が使われました。用語は `search_glossary` で調べています。
- Q1 は用語集の検索が 2 回から 1 回に減り、呼び出しは 3 回から 2 回になりました。モデル応答回数は 3 問とも実験１と同じです（2 回）。

## 2. 取得ページの違い（traces.md）

ヒットしたページの前後 1 ページが加わり、取得ページ数が 2〜3 倍になりました。

| 質問 | 実験１の取得ページ（ヒット） | 実験２の取得ページ（ヒット＋前後） |
|---|---|---|
| Q1（lec02） | p.47, 51, 52, 54, 60（5 ページ） | p.46, 47, 48, 50, 51, 52, 53, 54, 55, 59, 60, 61（12 ページ） |
| Q2（lec03） | p.13, 38, 39, 40, 65（5 ページ） | p.12, 13, 14, 37, 38, 39, 40, 41, 64, 65, 66（11 ページ） |
| Q3 | lec01 p.19、lec02 p.13, 24、lec03 p.19, 64（5 ページ） | lec01 p.18〜20、lec02 p.12〜14, 23〜25、lec03 p.18〜20, 63〜65（15 ページ） |

- 実験２のログの各結果には `role`（`hit` / `neighbor`）が付いています。`hit` のページは 3 問とも実験１の取得ページと完全に一致しました（Q1: p.47, 51, 52, 54, 60 / Q2: p.13, 38, 39, 40, 65 / Q3: lec01 p.19、lec02 p.13, 24、lec03 p.19, 64）。残りが前後ページ（`neighbor`）です。
- 隣接するヒットは重なるため、単純に 3 倍にはなりません。Q2 では p.37〜41 と p.64〜66 が連続した範囲になります。
- Q2 の p.37 と p.41 のように、実験１では取得されなかった「周辺ページ」が拾えるようになりました。

## 3. 回答で引用されたページの違い（differences.md）

| 質問 | 実験１の引用ページ | 実験２の引用ページ | 差 |
|---|---|---|---|
| Q1 | p.51, 52（＋用語集） | p.51, 52（＋用語集） | 同じ。前後ページは引用されず |
| Q2 | p.13, 38, 39, 40, 65 | p.13, 39, 40 | p.38 と p.65 が引用されなくなった |
| Q3 | lec02 p.13 | lec01 p.19, lec02 p.13 | lec01 p.19 が加わった |

- 取得ページが増えたのに、引用ページが増えたとは言えません。引用された新規ページはゼロで、Q2 ではむしろ減りました。
- Q2 で p.38 と p.65 が引用されなくなった理由は、ログからは断定できません。取得ページ増加による情報量の分散か、モデルの回答のゆらぎの可能性があります。
- 実験２の Q2 の回答は、実験１のように「p.65 の画像・文書の詳細が失われる」といった補足を書いていません。
- 実験２で新たに取得された前後ページ（p.14, 37, 41, 64, 66 など）が回答の根拠として引用された例は、3 問すべてで確認できません。
- 引用ページの数え方は両実験とも「回答文を読んで、根拠として挙げられたページ」に統一しました。実験２は全文を読み直し、機械抽出と同じ結果であることを確認しています。Q3 の lec01 p.19 は「出所」として明示されているので、引用に数えています（実験１では取得のみ）。

## 4. 回答内容の違い

- Q1: 回答の骨子は同じです。LoRA は元の重みを固定して低ランクの小行列 A・B だけを学習し、QLoRA はさらに元の重みを量子化します。実験２は用語集と p.51〜52 を根拠として明示しています。
- Q2: コンパクション（同一セッション内の履歴要約）、セッションをまたぐメモリ（外部保存して再読込）、日々のメモが全部は長期メモリにならない点は、どちらの実験でも同じです。実験２では p.65 由来の補足が消え、構成が少し簡潔になりました。
- Q3: どちらも「資料に実測値の記載はない」と結論づけ、数値を作り出していません。実験２では lec01 p.19 の「回答数 1 万件＋」と、lec02 p.13 の「5 回中 3 回正しい」を例として挙げ、これらが実測値ではないと説明しています。

つまり、前後ページを取得しても回答の正否や結論は変わらず、引用元もほとんど変わっていません。

## 5. コスト・時間の違い（benchmark_agent.md）

| 質問 | 入力 tokens（実験１→２） | 出力 tokens | 時間（秒） | 推定コスト USD |
|---|---|---|---|---|
| Q1 | 4,729 → 8,022（+70%） | 311 → 252 | 2.48 → 3.08 | 0.002196 → 0.003037（+38%） |
| Q2 | 3,550 → 6,462（+82%） | 621 → 495 | 3.43 → 3.51 | 0.002618 → 0.003176（+21%） |
| Q3 | 4,257 → 9,063（+113%） | 177 → 178 | 2.33 → 2.92 | 0.001720 → 0.003164（+84%） |

- 入力 tokens は 1.7〜2.1 倍になりました。取得ページ数の増加（5 → 11〜15 ページ）が主因と考えられます。
- 出力 tokens は Q1・Q2 で減り、Q3 はほぼ同じです。
- 時間は 0.1〜0.6 秒の増加で、モデル応答回数が同じなので差は小さい範囲です。ただし、1 回ずつの測定のため、ばらつきを含みます。
- それでも、他方式（全文投入は約 117,000 tokens、Tree・Graph は約 5,000〜13,000 tokens）と比べると、実験２のベクトル検索は低コストの範囲に収まっています。

## 6. まとめ

| 観点 | `search_materials()` のみ（実験１） | `search_materials_with_context()` を既定にした（実験２） |
|---|---|---|
| 取得範囲 | ヒットページのみ（各質問 5 ページ） | ヒット＋前後 1 ページ（11〜15 ページ） |
| ツール呼び出し | Q1 で 3 回 | Q1 で 2 回（用語集の重複検索が 1 回減った） |
| 引用ページ | Q2 で 5 ページ | Q2 で 3 ページ（前後ページの引用なし） |
| 回答の質・結論 | 3 問とも妥当 | 3 問とも妥当。実験１と実質同等 |
| 入力 tokens・コスト | 小さい | 1.7〜2.1 倍、コスト +21〜84% |
| 指示文の遵守 | — | 用語質問の Q1 でも `search_materials_with_context()` が使われた |

- 今回の 3 問では、前後ページの取得による回答品質の改善は観測できませんでした。コストだけが増えています。
- 前後ページが効くのは、答えがヒットページの周辺にまたがる質問だと考えられます。今回の質問は、ヒットページ単体で答えが完結していました。
- 実験２の指示文は、用語質問のときだけ `search_materials()` を使う意図でした。しかし Q1（用語質問）でも `search_materials_with_context()` が呼ばれており、指示文の分岐は今回の実行では働いていません。分岐の条件を明確にするか、プロンプトを見直す余地があります。
- 質問は 3 問、各条件 1 回の実行です。結論は傾向として読み、確かめるには複数回の実行や質問の追加が必要です。
